# M178

## Design

### M178 — `annotate`'s description says how to search for a phrase *(unplanned)* (2026-11-20)

[#469](https://github.com/utyagi24/klarpdf/issues/469). Found while the owner reviewed the
`annotate` tool description. The description told a caller to get a phrase's boxes from `search`,
and to pass a hit's `boxes` as one mark. It did not say to search with `whole_words: true`. With the
default, `whole_words: false`, `search` treats the query as separate words and returns a hit for
each word. A caller who followed the description got one highlight per word. They also got a
highlight on every other place either word appears. The resource `klarpdf://docs/annotate` had the
same gap.

This milestone was numbered M179 until 2026-11-23. The owner asked that the numbers follow the order
of building. This fix is built first, so it took M178.

**Surfaces: the bridge only.** Only text changes: the `annotate` description in
`klarpdf/mcp_bridge/server.py` and its entry in `klarpdf/mcp_bridge/docs.py`. No code changes, and
the app is not affected.

#### What was measured

A one-page PDF where "New York" wraps after "New" (`insert_textbox`, 118 pt wide, 11 pt):

| How the phrase was searched and marked | Highlights written |
|---|---|
| `search` with `whole_words: true`, then one mark with both of the hit's boxes | 1 |
| The same hit, as one mark per box | 2 |
| `search` with the default `whole_words: false`, one mark per hit | 2 (the search returned "New" and "York" as separate hits) |

#### What changed

* **The paragraph on where marks go** (owner's review, 2026-11-19). It now says: search with
  `whole_words: true`, make one mark from each hit with its `page` and all its `boxes`, and do not
  mark a phrase word by word. It no longer names `extract_text` as a source of boxes, because
  `extract_text` returns none. The owner's first wording made the description 63 characters over
  its 1,900-character budget, so the text that went in is a shorter version of it.
* **The paragraph on passing every mark in one call** is one sentence now, in the owner's words
  (2026-11-20): "Pass every mark for the document in one call to avoid creating intermediate
  copies."
* **The resource.** The section "Marking a phrase, not its words" starts with a paragraph that says
  to use `whole_words: true`, and what the default returns instead.
* **A test runs the description's steps.** `tests/test_mcp_annotations.py` builds the wrapped
  "New York" page. It checks that the default search returns two hits, that the phrase search
  returns one hit with two boxes, and that the hit as one mark is one highlight. Splitting the hit
  into one mark per box makes it fail (2 highlights, not 1).

The description is 1,799 characters, up from 1,788.

#### Not in this milestone

[#468](https://github.com/utyagi24/klarpdf/issues/468), found in the same review: a misspelled key
inside a mark, such as `colour`, is ignored with no error. That is a code change and has its own
